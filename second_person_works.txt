# ۲. وظیفه اول: طراحی رابط دسکتاپ

مهم‌ترین بخش مسئولیت تو ساخت Desktop Application است.

نرم‌افزار باید با PySide6 ساخته شود و روی Windows و Linux اجرا شود.

## بخش‌های اصلی رابط کاربری

### A. Dashboard

صفحه اصلی برنامه باید شامل موارد زیر باشد:

- نام و لوگوی CodeMind AI
- ایجاد پروژه جدید
- باز کردن پروژه قبلی
- نمایش پروژه‌های اخیر
- تعداد تحلیل‌های انجام‌شده
- وضعیت موتور تحلیل
- وضعیت AI Engine
- وضعیت آفلاین بودن برنامه

### B. Code Editor

یک محیط ویرایش کد حرفه‌ای طراحی کن.

قابلیت‌های موردنیاز:

- نمایش شماره خطوط
- Syntax Highlighting برای Python
- تشخیص خطوط دارای خطا
- انتخاب و کپی کد
- باز و بسته کردن فایل‌ها
- چند Tab هم‌زمان
- جست‌وجو در کد
- ذخیره فایل
- نمایش خطاها در کنار کد

برای ویرایشگر می‌توانی از QScintilla یا یک ویرایشگر مناسب مبتنی بر Qt استفاده کنی.

### C. Analysis Panel

این قسمت نتایج تحلیل موتور اصلی را نمایش می‌دهد.

هر خطا باید شامل موارد زیر باشد:

- نام خطا
- نوع خطا
- شدت خطا
- نام فایل
- شماره خط
- توضیح
- پیشنهاد اصلاح
- منبع تشخیص
- میزان اطمینان

کاربر باید بتواند روی هر خطا کلیک کند و مستقیماً به خط مربوطه در ویرایشگر منتقل شود.

### D. Debug Panel

یک پنل برای نمایش اطلاعات دیباگ طراحی کن:

- Call Stack
- Variables
- Execution Steps
- Traceback
- Runtime Information

### E. AI Assistant Panel

یک پنل جداگانه برای تعامل با موتور هوش مصنوعی داشته باشیم.

قابلیت‌ها:

- توضیح خطا
- توضیح بخش انتخاب‌شده کد
- پیشنهاد اصلاح
- پرسش درباره کد
- نمایش پاسخ مدل محلی
- نمایش وضعیت فعال یا غیرفعال بودن AI

اگر مدل AI در دسترس نبود، رابط باید همچنان با قابلیت‌های عادی کار کند.

# ۱۰. نحوه ارتباط با برنامه‌نویس اول

مهم‌ترین اصل همکاری این است که تو نباید موتور تحلیل را دوباره پیاده‌سازی کنی.

برنامه‌نویس اول مسئول Core Engine است و تو مسئول استفاده از آن در محصول هستی.

خروجی موتور تحلیل باید یک ساختار استاندارد داشته باشد.

نمونه:

{
  "rule_id": "PY001",
  "severity": "error",
  "category": "syntax",
  "message": "Invalid syntax",
  "file": "main.py",
  "line": 12,
  "column": 5,
  "confidence": 1.0,
  "source": "parser",
  "suggestion": null
}

تو باید بتوانی این اطلاعات را دریافت و در رابط کاربری نمایش دهی.

برای API نیز با برنامه‌نویس اول توافق کن.

Endpointهای پیشنهادی:

POST /api/v1/projects
GET /api/v1/projects
POST /api/v1/analyze
GET /api/v1/analysis/{analysis_id}
POST /api/v1/fixes/preview
POST /api/v1/fixes/apply
POST /api/v1/reports/export
GET /api/v1/system/status

ساختار دقیق درخواست و پاسخ هر Endpoint باید پیش از پیاده‌سازی مشترکاً مشخص شود.
