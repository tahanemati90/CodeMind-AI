# CodeMind AI
## Software Architecture Document (SAD)

**Version:** 1.0  
**Architecture Style:** Modular Layered Architecture  
**Core Language:** Python

---

## 1. معماری کلی

CodeMind AI از چند لایه مستقل تشکیل می‌شود:

1. Presentation Layer
2. Application Service Layer
3. Core Analysis Layer
4. Intelligence Layer
5. Data Layer
6. Security Layer

هر لایه مسئولیت مشخصی دارد و ارتباط میان آن‌ها از طریق رابط‌های تعریف‌شده انجام می‌شود.

## 2. Presentation Layer

مسئول ارتباط با کاربر است.

### Desktop Client
Technology: PySide6

مسئولیت‌ها:
- نمایش و ویرایش کد
- نمایش نتایج تحلیل
- مدیریت پروژه
- نمایش خطاها و هشدارها
- نمایش پیشنهاد اصلاح
- نمایش نمودار مسیر اجرا

### Web Client
Technology: HTML, CSS, JavaScript

مسئولیت‌ها:
- ارائه رابط مرورگری
- نمایش کد و گزارش‌ها
- مدیریت پروژه
- ارسال درخواست تحلیل
- دریافت نتایج از سرویس محلی

### PWA
مسئولیت‌ها:
- نصب‌پذیری
- ذخیره رابط کاربری
- قابلیت استفاده از امکانات مستقل از سرور
- اتصال به سرویس محلی در صورت دسترسی

## 3. Application Service Layer

Technology: Python + FastAPI

مسئولیت‌ها:
- دریافت درخواست‌ها
- اعتبارسنجی ورودی
- مدیریت عملیات تحلیل
- مدیریت پروژه‌ها
- مدیریت گزارش‌ها
- هماهنگی میان ماژول‌های Core و UI

این لایه نباید مستقیماً منطق تحلیل کد را پیاده‌سازی کند.

## 4. Core Analysis Layer

هسته اصلی و اختصاصی نرم‌افزار.

### Parser Engine
Technology: ast, tokenize, symtable

وظایف:
- تبدیل کد به ساختار قابل‌تحلیل
- استخراج توابع و کلاس‌ها
- استخراج متغیرها
- ایجاد ساختار درختی AST

### Static Analyzer
وظایف:
- شناسایی خطاهای ایستا
- بررسی Scope
- بررسی متغیرها
- تحلیل Importها
- شناسایی الگوهای مشکوک

### Logic Analyzer
وظایف:
- تحلیل شرط‌ها
- بررسی جریان کنترل
- تحلیل مسیرهای اجرایی محدود
- شناسایی مشکلات منطقی قابل‌تشخیص

### Runtime Debugger
Technology: pdb / bdb / sys.settrace

وظایف:
- دریافت اطلاعات اجرای برنامه
- بررسی Call Stack
- ثبت تغییر متغیرها
- استخراج Traceback

### Performance Analyzer
وظایف:
- اندازه‌گیری زمان اجرا
- بررسی نقاط پرهزینه
- شناسایی عملیات تکراری
- تولید گزارش عملکرد

### Fix Engine
وظایف:
- تولید پیشنهاد اصلاح
- مدیریت Patchها
- مقایسه کد قبل و بعد
- کنترل سازگاری اصلاحات

## 5. Intelligence Layer

### Rule-Based Engine
- اجرای قوانین اختصاصی
- اولویت‌بندی هشدارها
- ترکیب نتایج تحلیل‌گرها
- تولید توضیحات ساختاریافته

### Local AI Engine
Technology: llama.cpp / GGUF

وظایف:
- دریافت توضیح خطا و بخش مرتبط کد
- تحلیل زبانی
- تولید پیشنهاد اصلاح
- توضیح آموزشی

مدل زبانی اختیاری است و خاموش بودن آن نباید عملکرد هسته اصلی را مختل کند.

### AI Manager
- بررسی منابع سخت‌افزاری
- مدیریت فعال‌سازی مدل
- محدودسازی اندازه درخواست
- کنترل مصرف حافظه
- مدیریت خطاهای مدل
- ارائه حالت جایگزین

## 6. Data Layer

Technology: SQLite + JSON

اطلاعات ذخیره‌شده:
- تنظیمات کاربر
- تاریخچه تحلیل‌ها
- اطلاعات پروژه‌ها
- نتایج گزارش‌ها
- تنظیمات AI
- سوابق پیشنهادهای اصلاح

ذخیره محتوای کد کاربر باید تحت کنترل او باشد.

## 7. Security Layer

مسئولیت‌ها:
- اجرای کد در پردازش جداگانه
- محدودسازی زمان اجرا
- محدودسازی منابع
- محدودسازی دسترسی فایل
- کنترل دسترسی شبکه
- جلوگیری از اجرای ناخواسته کد
- محافظت از فایل‌های پروژه

توجه: پردازش جداگانه به‌تنهایی Sandbox امن نیست. اجرای کد غیرقابل‌اعتماد باید در محیط ایزوله واقعی انجام شود.

## 8. قرارداد خروجی تحلیل

تمام تحلیل‌گرها باید خروجی یکسان داشته باشند.

ساختار پیشنهادی:

{
  "rule_id": "PY001",
  "severity": "error",
  "category": "syntax",
  "message": "Invalid syntax",
  "file": "main.py",
  "line": 12,
  "column": 5,
  "confidence": 1.0,
  "source": "parser",
  "suggestion": null
}

فیلدها:
- rule_id: شناسه قانون
- severity: شدت مشکل
- category: دسته مشکل
- message: توضیح
- file: فایل مربوطه
- line: شماره خط
- column: شماره ستون
- confidence: میزان اطمینان
- source: منبع تشخیص
- suggestion: پیشنهاد اصلاح

## 9. ارتباط ماژول‌ها

Desktop و Web از طریق Application Service با Core ارتباط برقرار می‌کنند.

Core نتایج را به قالب Diagnostic تبدیل می‌کند.

Intelligence Layer می‌تواند نتایج چند تحلیل‌گر را ترکیب کند.

Fix Engine پیشنهادهای اصلاح را به شکل Patch ارائه می‌دهد.

کاربر باید پیش از اعمال Patch تأیید کند.

## 10. اصول مهم معماری

- عدم وابستگی Core به رابط کاربری
- استفاده از Dependency Injection در نقاط لازم
- جداسازی منطق از نمایش
- استفاده از قراردادهای داده مشترک
- تست مستقل ماژول‌ها
- جلوگیری از اجرای هم‌زمان تحلیل‌های سنگین بدون کنترل منابع
- عدم نیاز به GPU برای قابلیت‌های اصلی
